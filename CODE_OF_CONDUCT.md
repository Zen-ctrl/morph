# MORPH code of conduct

MORPH welcomes thoughtful technical collaboration. Participants are expected to make the
project safer, clearer, and easier to verify.

## Expected behavior

- Be respectful, specific, and constructive.
- Critique ideas, code, evidence, and tradeoffs rather than people.
- Make room for different experience levels and communication styles.
- Give credit for work and preserve legitimate upstream attribution.
- Protect private data, credentials, unpublished findings, and security reports.
- Accept maintainer decisions about scope while remaining free to document a technical disagreement.
- Correct mistakes openly and without retaliation.

## Unacceptable behavior

- Harassment, discrimination, threats, intimidation, or targeted personal attacks.
- Sexualized language or attention.
- Deliberate misrepresentation of benchmarks, authorship, identity, or project status.
- Publishing another person's private information without explicit permission.
- Pressuring someone to reveal credentials, private datasets, or confidential reports.
- Sustained disruption of issues, reviews, or project communication.

## Scope

This code applies in repository issues, pull requests, reviews, discussions, release work,
and project-related private communication.

## Reporting

Report conduct concerns privately to a repository maintainer through an available private
collaboration channel. If no private channel is available, open an issue containing only a
request for private maintainer contact. Do not include sensitive details in a public or
broadly visible issue.

Security vulnerabilities follow `SECURITY.md`, not the conduct-reporting path.

## Enforcement

Maintainers may edit or remove content, pause a discussion, reject a contribution, restrict
participation, or remove repository access when necessary to protect participants and the
project. Reports will be reviewed as privately and impartially as the available repository
tools permit. No response-time guarantee is made.
